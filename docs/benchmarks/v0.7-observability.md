# v0.7 observability microbenchmarks

Measured on 2026-10-02 with AMD Ryzen 7 6800H (8 cores, 16 logical), Windows
11 Home Single Language build 26200, amd64, Go 1.25.4. No network services
were involved. Tracing used a no-op in-memory exporter with a bounded queue;
sampled and unsampled modes used ratios 1.0 and 0.0 respectively. This is not
an OTLP network throughput benchmark.

```powershell
go test ./internal/observability -run=^$ -bench='Benchmark(RequestInstrumentation|SecurityEventSnapshotCollector|UpstreamPropagation)' -benchmem -count=1 -benchtime=200ms
```

| Scenario | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| Request instrumentation disabled | 148.4 | 208 | 4 |
| Prometheus metrics enabled | 544.1 | 611 | 8 |
| Tracing enabled, unsampled | 1067 | 1376 | 18 |
| Tracing enabled, sampled | 1991 | 2410 | 21 |
| Security-event collector registry gather | 68248 | 80883 | 580 |
| W3C upstream propagation | 491.2 | 536 | 8 |

The request benchmark sends a GET through the observability middleware to an
in-memory handler/recorder. It excludes routing, auth, Redis, WAF, reverse
proxy, access-log I/O, actual HTTP sockets, and network export. The metrics
case records a completed request; the tracing cases end a server span. The
collector case gathers the entire private registry, including Go/process
collectors, not just the lightweight pipeline snapshot. The propagation case
injects into a fresh header map; it excludes upstream networking. All run at
benchmark default serial concurrency for 200 ms per case, with no payload and
no errors. These local results show relative instrumentation cost in this
setup only; they are not a production latency, capacity, or universal
performance guarantee. Compare with a representative end-to-end load test
before choosing sampling or SLO thresholds.

The pre-change v0.6 pipeline baseline on the same machine with `-benchtime=500ms`
was: accepted `Publish` 39.38 ns/op, zero allocations; full-queue drop 14.12
ns/op, zero allocations; below-threshold detector 152.4 ns/op, 288 B/op and
one allocation; alerting detector 156.7 ns/op, 288 B/op and one allocation.
These cases are independent of the HTTP instrumentation benchmark and should
not be directly compared as request-path costs.

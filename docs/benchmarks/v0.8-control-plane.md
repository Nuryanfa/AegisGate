# v0.8 control-plane microbenchmarks

Measured 2026-10-03 on Windows/amd64, Go 1.25.4, AMD Ryzen 7 6800H with Radeon Graphics, `GOMAXPROCS=16`. Command:

```sh
go test ./internal/controlplane -run '^$' -bench '^Benchmark' -benchtime=200ms -count=3 -benchmem
```

Fixture: one public route to `http://localhost:8081`, no API clients, WAF, Redis, network transport, or request body. Compilation uses a `2s` local write timeout and a disabled tracing/metrics path. The fan-out fixture has 32 registered, buffered in-memory subscribers, each with one pending slot; it publishes changed upstream URLs. Benchmark concurrency is one driving goroutine (the fan-out operation visits 32 subscribers synchronously). Each sample runs approximately 200 ms; all iterations completed without benchmark errors. Values below are representative ranges from three samples, not a capacity or throughput promise.

| Operation | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| Atomic runtime pointer load | 0.246–0.257 | 0 | 0 |
| Compile one runtime | 2,156–2,245 | 1,729 | 24 |
| Compile and apply a changed revision | 2,360–2,416 | 1,761 | 26 |
| Canonical revision calculation | 3,189–4,783 | 1,729 | 29 |
| Protobuf marshal and unmarshal | 974–1,052 | 424 | 9 |
| Publish to 32 in-memory subscribers | 9,315–9,881 | 2,738 | 46 |

The pointer-load figure is a narrow in-process microbenchmark and does not measure full HTTP dispatch, policy checks, contention, or network latency. The compilation and apply measurements do not include YAML loading, gRPC transport, TLS, Redis, or upstream traffic. Fan-out measures queue replacement, not delivery over real sockets or ACK latency. For the v0.7 request-instrumentation baseline and its different scenario, see [v0.7 measurements](v0.7-observability.md); these numbers are not directly comparable to that HTTP benchmark. Use an end-to-end load test before making any production capacity claim.

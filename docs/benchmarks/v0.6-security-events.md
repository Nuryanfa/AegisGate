# v0.6 security-event microbenchmarks

Measured on 2026-10-02.

## Environment

- Hardware: AMD Ryzen 7 6800H, 8 cores / 16 logical processors
- Operating system: Windows 11 Home Single Language, build 26200, amd64
- Go: `go1.25.4 windows/amd64`
- Package: `internal/securityevent`
- External services: none

## Command

```powershell
go test ./internal/securityevent -run=^$ -bench='Benchmark(Publish|Detector)' -benchmem -count=1 -benchtime=500ms
```

## Inputs

- `Publish/accepted` uses one preconstructed immutable WAF event and an empty
  capacity-one ingress channel; the benchmark receives each accepted event so
  every iteration measures the accepted non-blocking publication path.
- `Publish/full_queue_drop` pre-fills a capacity-one ingress channel and
  measures drop-newest publication. No detector, worker, or sink is involved,
  which demonstrates that the HTTP-facing operation does not wait for sink
  delivery.
- `Detector/below_threshold` processes one rule ID under a deliberately
  unreachable threshold in one long fixed window.
- `Detector/generates_alert` uses threshold one and a one-nanosecond clock step
  and cooldown, producing one typed alert for every processed event.

These are local single-process microbenchmarks, not deployed throughput or
latency claims. They exclude HTTP parsing, WAF evaluation, scheduling under
production load, structured-log I/O, network transport, container limits, and
failure conditions. Re-run them on the target platform before using them for
capacity planning.
